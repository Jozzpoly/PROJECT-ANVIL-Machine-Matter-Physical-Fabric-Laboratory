## C5A / Product Behavior — PASS

Canonical detailed record: `docs/studio/P06-C5A-PRODUCT-BEHAVIOR.md`.

Shortest product constitution:

> **I build persistent matter. I give physical meaning to places on it. Studio continuously determines whether that authored composition can currently be realized. RUN creates a fresh disposable physical realization. I observe it, pause it and trace why it behaved that way. STOP discards the realization, not my construction. If I exceed ANVIL's earned capability, my authored intent survives and Studio tells me honestly that the composition is not yet supported.**

Core behavioral rules:

- BUILD edits what persists;
- RUN creates a fresh disposable physical realization and never writes runtime pose back to source by default;
- PAUSE preserves realization for STEP/TRACE but is not arbitrary persistent authoring;
- STOP disposes runtime, preserves authored construction/camera/workspace context;
- local meaning is experienced as meaning attached to a place on matter, not a generic component model;
- no required COMPOSE/Compile ceremony: current authored combination is already the composition;
- compilation/lowering remains silent while successful and explainable when blocking/interesting;
- product truth distinguishes READY, INVALID, UNSUPPORTED, REQUIRES BUILD and RUNTIME FAULT;
- `UNSUPPORTED != INVALID`; unsupported authored intent survives;
- authored actions follow `TARGET → PREVIEW/DRAFT → COMMIT → RECOMPILE/RECLASSIFY → SPATIAL FEEDBACK`;
- runtime evolution is not authored undo history;
- accepted CUT remains a qualified topology intervention, not a generic free editor tool.

First real Studio journey:

BUILD → author local BEARING → author local TORQUE-PATCH → RUN → ACTIVATE → observe → PAUSE → TRACE → STOP → MODIFY → RUN AGAIN.
