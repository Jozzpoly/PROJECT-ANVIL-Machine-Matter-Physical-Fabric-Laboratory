## Evidence classes kept separate

### A — technical integration truth

Automated and provenance-backed evidence may establish that:

- the frozen B0 state machine is enforced;
- the accepted CUT/rebuild/re-lower sequence executes correctly;
- authored source identity and disposable runtime identity remain separated;
- fresh post-CUT activation starts OFF;
- the fresh action binds the rebound endpoint rather than the stale sibling;
- bounded post-CUT activation produces the already-accepted causal behavior;
- no new physical/semantic rule or generic ontology was introduced;
- existing ANVIL regressions remain green.

A PASS here proves W1 implementation/integration only.

### B — informed owner value

The owner already knows substantial project history and expected semantics. W1 therefore may test whether the abstraction is useful to an informed owner, but it must not claim that the owner independently discovered the intended model from the UI.

For `VALUE SIGNAL`, require all three discriminators below.

#### B1 — mental model

The owner can describe the important distinction primarily in authored/runtime terms rather than reducing it to current Box3D body/joint identity.

#### B2 — novel prediction

The owner can make at least one concrete prediction about a plausible hypothetical modification not just replayed by the specimen. The prediction should follow from the authored/local-capability model rather than from memorized B0 instructions.

This is qualitative owner evidence; it is not a new physics claim and the hypothetical modification need not be implemented during W1.

#### B3 — creative pull

The owner identifies at least one concrete thing they would now want to author, change, compose, or probe because the Physical Fabric model suggests an interesting outcome.

A strong signal is expressed in terms such as authored matter, locality, interface, capability, topology or composition. A weak signal merely requests another prepared joint, body, button or visual effect.

This restores the strategic discriminator present in the original W0 design reasoning without adding any new B0 interaction or implementation freedom.

### C — naïve discoverability

Whether an uninformed person would independently infer the authored/runtime distinction from the specimen is **UNKNOWN** unless separately tested with an actually uninformed observer.

The informed owner gate must not be reported as evidence for naïve discoverability.

W1 does not require Class C to complete.

## Owner verdict rules

### VALUE SIGNAL

Allowed only when:

1. technical integration truth is established;
2. the owner regards the composition as more than a prepared mechanism;
3. B1 mental model is present;
4. B2 novel prediction is present;
5. B3 creative pull is present.

Interpretation: the current composition has earned enough owner-value signal to justify a post-W1 Research Compass comparison of possible next freedoms. It does not select ANVIL-11 automatically.

### LEGIBLE BUT SCRIPTED

Use when the implementation is understandable/correct but one or more of B1–B3 is absent, weak, or dominated by the prepared fixture.

Interpretation: investigate authorship freedom, locality/representation, editing, emergence or fixture scripting before automatically adding more physics primitives.

### NO VALUE SIGNAL

Use when the composition does not provide a useful Physical Fabric abstraction even after technically correct presentation.

Interpretation: reopen the macro hypothesis rather than polishing the same specimen until it becomes persuasive.

## Implementation sequence and checkpoints

W1 implementation remains bounded by `W0-FINAL-SCOPE.md` and proceeds in this order:

### P1 — executable state contract

Build the smallest Workbench-specific phase controller and tests that enforce the frozen B0 transitions. Do not prioritize rendering or visual polish.

Required properties:

- deterministic path to CUT READY;
- no pre-CUT torque activation;

### P2 — real transaction composition

Compose the accepted pre-CUT REBIND path, CUT, motion transfer, runtime disposal/rebuild, BEARING reconstruction and same-source TORQUE-PATCH re-lowering.

Checkpoint after P1 + P2: run a meso audit before investing in presentation. Confirm the implementation is still thin integration and no new semantics have been smuggled in.

### P3 — bounded causal observation

Connect fresh post-CUT activation and the accepted bounded causal observation/control path.

### P4 — owner-facing representation

Only after the executable integration is sound, add the frozen authored/runtime/both views and bounded interaction presentation required by W0.

### P5 — candidate / owner gate

Run Draft/core then Ready/candidate validation from W0, hand off the exact artifact, obtain the informed owner verdict under this gate, then run a macro Research Compass checkpoint before selecting any new frontier.

## Stop / reclassification rules

All W0 stop rules remain authoritative. In addition, stop ordinary implementation for review when:

- a helper starts defining new authored semantics rather than adapting existing experiment-local APIs;
- implementation complexity rises while the owner-information gain of B0 remains flat;
- UI work begins compensating for a weak underlying composition by explaining the expected answer too aggressively;
- a technically green result is being treated as `VALUE SIGNAL` without B1–B3;
- current cell/body/joint identities begin to function as hidden ontology;
