## Studio north star

**ANVIL Studio is one long-lived interactive 3D laboratory for Physical Fabric.**

North-star loop:

`CREATE MATTER → GIVE IT LOCAL MEANING → COMPOSE → SIMULATE → OBSERVE → MODIFY → DISCOVER`

Product-behavior form:

`BUILD → GIVE LOCAL MEANING → RUN → OBSERVE → PAUSE / TRACE → STOP → MODIFY → RUN AGAIN`

The world is the product. UI supplies tools and reveals truth when needed; it must not become an evidence dashboard, owner gate, set of experiment routes, generic CAD/game editor or ontology browser.

## C5A product constitution

The shortest accepted mental model is:

> **I build persistent matter. I give physical meaning to places on it. Studio continuously determines whether that authored composition can currently be realized. RUN creates a fresh disposable physical realization. I observe it, pause it and trace why it behaved that way. STOP discards the realization, not my construction. If I exceed ANVIL's earned capability, my authored intent survives and Studio tells me honestly that the composition is not yet supported.**

Consequences:

- `BUILD` edits what should persist;
- `RUN` creates a fresh disposable realization and does not write runtime pose/motion back to source;
- `PAUSE` preserves a live realization for inspection/STEP, not arbitrary persistent authoring;
- `STOP` disposes runtime and returns to the authored construction;
- local meaning is experienced as meaning attached to a place on matter, not as a generic Entity/Component model;
- there is no required user action called COMPOSE: authored composition already exists after matter + meanings are created;
- compilation/lowering should be silent when successful and explainable when blocking or interesting;
- physical/spatial evidence comes before technical text.

## Product truth states

Do not collapse these categories:

- **READY** — current authored composition can be realized;
- **INVALID** — authored intent violates the current authored/semantic contract;
- **UNSUPPORTED** — intent may be meaningful, but ANVIL has not qualified the requested composition;
- **REQUIRES BUILD** — requested persistent edit cannot be honestly performed against a live realization; return to BUILD;
- **RUNTIME FAULT** — source/composition passed validation but execution failed technically.

`UNSUPPORTED != INVALID` is a core Studio rule. Unsupported authored intent should normally survive rather than being silently deleted or rewritten.

## C5A interaction grammar

Persistent authoring follows the behavioral sequence:

`TARGET → PREVIEW / DRAFT → COMMIT → RECOMPILE / RECLASSIFY → IMMEDIATE SPATIAL FEEDBACK`

Before COMMIT, cancellation must not mutate authored truth.

Grounded behaviors include:

- selection is non-mutating and source/runtime selection identities remain distinct;
- ADD MATTER uses a preview/draft before persistent commit;
- REMOVE MATTER previews affected local meanings and does not silently cascade-delete them;
- material changes are authored changes and may require BUILD;
- BEARING authoring targets a local interface/seam and free axis spatially, without manual source IDs;
- TORQUE-PATCH authoring targets an eligible local place/face and remains persistent authored intent;
- RUN creates a fresh runtime session;
- ACTIVATE is runtime-only transient state;
- PAUSE preserves runtime for inspection;
- STEP advances runtime only and never belongs to authored undo history;
- STOP disposes runtime but preserves source/camera/workspace context;
- RESTART creates another fresh realization from the same current authored truth;
- TRACE/INSPECT is presentation/instrumentation and must use provenance rather than pretending disposable identity persisted through rebuild.

Accepted CUT evidence remains a **qualified topology intervention**, not a generic free CUT tool or permission for arbitrary live source editing.
