## Question

> Can the WER-1D actionability-coupled Bearing disclosure model be implemented as a bounded experiment on the current R2 substrate without changing source/runtime authority, hiding authored Meaning, filtering Owner choices, or creating invisible candidate interaction?

A positive result may authorize a later Owner comparative gate. It does not establish that the disclosure policy is better, intuitive for naive users, final UI, or final Meaning grammar.

## Frozen experiment scope

Three policies exist only for this bounded experiment:

1. `baseline` — current persistent shared-interface affordance/control behavior;
2. `global` — quiet neutral potential Bearing opportunities; under `B`, all current adjacent-Matter opportunities are disclosed and activated;
3. `local` — the same quiet neutral state; under `B`, only opportunities inside the frozen local wake radius are disclosed and activated.

Torque disclosure is not optimized in WER-1Q. Existing authored Torque remains Meaning and its current authoring/reachability paths must remain intact.

## Local experiment ontology

- `M` — authored Meaning referent. Persistent/reachable when a truthful spatial referent survives.
- `P` — potential Bearing opportunity: a shared interface between two currently adjacent authored Matter cells across opposite faces, regardless of existing Bearing or predicted runtime quality.
- `S` — ordinary Matter action surface.

`P` is derived from authored topology, not from generic `R2InterfaceHit` identity and not from realization success.

Consequences frozen before qualification:

- a seam already containing a Bearing remains `P` so duplicate/conflict authoring remains possible;
- a seam that later produces `RIGID_BYPASS` remains `P`;
- an orphan Bearing with one missing Matter endpoint remains `M` but is not `P`;
- dormant undisclosed `P` must not intercept `S`;
- when `P` is disclosed, visibility and candidate interaction are coupled with the same policy/tolerance;
- runtime viability never filters candidate membership.

## Implementation boundary

WER-1Q changes only bounded presentation–interaction substrate:

- experiment-local policy/topology module `src/studio-r2/actionability-disclosure.ts`;
- bounded candidate metadata/routing in `src/studio-r2/world.ts`;
- empty-seam semantic presentation follows the same disclosure policy;
- Node topology guards and real-Chromium qualification tests.

It does not intentionally change:

- authored source schema;
- Bearing/Torque identity;
- realization/runtime/physics;
- diagnostics semantics;
- exact-delete / Undo / Redo authority;
- PARTIAL/MATTER_ONLY RUN permission;
- current Bearing one-shot `B → compatible shared interface` grammar;
- camera or Matter renderer;
- authored Bearing/Torque glyph semantics;
- Pages promotion contract.

The experiment-local substrate is not final architecture and must not be generalized by inertia.

## Qualification guards

Before any Owner comparative trial, exact executable evidence must demonstrate at minimum:

1. quiet neutral has no invisible empty-candidate capture;
2. disclosed Bearing candidate is actually interactive;
3. global/local derive candidate membership from the same adjacent-Matter topology;
4. existing Bearing does not remove a candidate and duplicate conflict remains authorable;
5. `RIGID_BYPASS` opportunity is not prediction-filtered;
6. orphan Bearing remains reachable authored `M`, but is not reclassified as `P`;
7. standalone/single-anchor Torque remains reachable authored `M` when no `P` remains;
8. PARTIAL/MATTER_ONLY runtime remains attemptable and RUN is not permission-gated;
9. P1 authored-Meaning semantic-envelope behavior is not repurposed into latent candidate magnetism;
10. baseline regression, typecheck, Foundation/semantic/Box3D, production build and exact provenance remain green;
11. rendered evidence for quiet/global/local/orphan/standalone-Meaning states shows no obvious presentation–interaction contradiction.

A guard failure is a **PROTOCOL RED**, not evidence that one UX policy is better or worse.

## Evidence already available before Chromium qualification

Draft core qualification has already established that:

- the new source compiles;
- existing Node/Foundation/semantic/Box3D tests remain green after the implementation substrate;
- the WER-1 topology unit guard compiles in the bounded test build;
- `P` remains unchanged when an existing Bearing is authored;
- an orphan authored Bearing does not manufacture `P`;
- a topological seam later diagnosed `RIGID_BYPASS` remains `P`.

This is not enough for qualification because pointer hit-routing, wake-up behavior and rendered coupling require real Chromium.

## Pre-registered dispositions

### `OWNER-EVALUATION READY`

Only if all structural guards and full browser regression pass on one exact staged build and direct visual inspection reveals no obvious instrument defect.

### `PROTOCOL RED`

If a variant wins/works only by invisible input capture, changed tolerance, runtime-success filtering, lost authored Meaning, broken duplicate authoring, or another uncontrolled semantic change.

### `SUBSTRATE RED`

If truthful `M/P/S` coupling requires disproportionate R2 architecture work beyond the bounded experiment.

### `CONCEPT RED`

If the minimal coupled disclosure is executable but intrinsically misleading/unusable enough that a comparative Owner test would measure instrument defect rather than the hypothesis.
